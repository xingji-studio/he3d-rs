# 《HE3D 入门》大纲

这份文件是 `docs/getting-started.zh.md` 的内容规划。内部工作文档：不面向使用者，不配对英文版，
改完正文之后可以删。

## 读者与目标

主要读者：会 Rust、没写过 3D 的人。前置是读过语言基础，不解释 `Result`、`Option`、闭包与结构体。
用过别的引擎的人靠正文里的对照解决，不另写迁移指南。

读完的目标：能自己搭出「场景 + 相机 + 输入 + 物理」的小应用。

## 写作规则

规则写在 `docs/writing-style.zh.md`，写之前先读它。这份大纲依赖其中这几条：

- **六段**：一句话目标 → 能跑的代码 → 逐段解释 → 易犯之处（索引）→ 问与答 → 改一改。坑在
  第三段里就地给出，写成「症状 → 原因 → 怎么办」，编译失败的连 rustc 原文一起贴；第四段只是
  指向那些位置的三行索引。下面每章列出的「易犯之处」按这条规则就地落位。
- **正文可以内联指代**：类型名与 API 名首次标注后，正文用内联 code 指代，讲行为时用中文动词
  （「呈现一次」，不写「调用 `present`」）。方法名关在代码块里，问与答就没法提问。
- **问与答先给结论**（能／不能、该／不该、是／不是），再给机制，最后才是指针。问题可以因为太深而
  指向后面讲透它的那一章，但指针不能代替答案。
- **螺旋**：概念首现只给够用的深度，章末问与答追问一次，再由问与答指向讲透它的后章。
- **不写待做的题**；「改一改」留下，因为每一改都能当场看到结果。
- **正文只写现在是什么、怎么做**：不写「不是 X 而是 Y」「以前是 X」「曾经考虑过 X」
  「之所以没有 X，是因为……」。
- **数字只写两类**：工具链强制的（`rust-version`），以及能追到名字的常量（见文末对照表）。行数、
  示例长度、凭感觉的毫秒数不写。
- `trait` 保留英文不译；不自造译名。
- 章节标题不用口语（第三章叫「起步」，不叫「先把画面跑起来」）。
- 没有代码的章也可以设「问与答」（第 1 章就设）；第 15、16 章只做索引与取舍汇总，不设。「改一改」需要当场看到结果，没有代码的章一律不设（第 1、15、16 章）。

## 代码载体

- 正文程序用 `SdlBackend`，开窗画一个受光的旋转立方体。终端字符画面丑，也没必要。
- 新增一个沙盒示例 `examples/playground`（约 150 行）：一个静态地板、一个动态盒子、WASD 推、
  空格跳、相机跟随。第 8、9、11 章引用它；它用 `SdlBackend`，与其他示例一致；CI 只编译不运行它。
- 其余章节用片段。片段由 `crates/he3d-docs/build.rs` 抽取编译：取自第 5 章那段程序的片段自动
  获得该程序的 import，需要额外变量或程序之外的名字时，在 `build.rs` 的 `CONTEXTS` 里按片段首行
  加一条。指南文件本身保持普通 Markdown，不放任何为编译而写的东西。
- 因此 `crates/he3d-docs` 需要 `he3d-platform-sdl3` 依赖（工作区本来就因四个示例需要 SDL3）。
- 反例另立一张 `FAILING` 表，键同样是片段首行，登记「必须编译不过」的片段；`he3d-docs` 的测试
  为每个反例生成临时 crate、复制工作区 `Cargo.lock`、跑 `cargo check --offline` 并断言失败。
  不用 `trybuild`：本机 `~/.cargo/registry/src` 只读，装新 crate 会让本地构建直接坏掉。

## 章节目录

### 1. HE3D 是什么
**目标**：知道手上是什么，以及它按什么成本工作。
**小节**
1. 场景在 CPU 上逐像素画成一块 RGBA 像素缓冲，后端负责把它送出去。
2. 没有 GPU、没有着色器语言、不包装图形 API；开销按像素算。
3. 三条约定：右手系（`x` 右、`y` 上、`z` 前）；逆深度（存 `1/w`，有近平面、没有远平面）；
   纹理原点左上。
**载体**：表格。
**易犯之处**
- 把前方当成 `-Z` → 引擎约定 `+Z` 向前 → 表示前方用 `Vec3::Z`。
- 以为深度缓冲存的是距离 → 它存的是 `1/w` → 远处前后关系可能分不清，近处精度很高。
**问与答**
- 逆深度换来什么、代价是什么？→ **换来近处精度，而且不需要远裁剪面**；代价是远处前后关系可能
  分不清。（本章）
- 这引擎适合做什么？→ **可控规模的低多边形场景，以及需要可移植或无显示设备的场合**；追求画质的
  项目不适合。（本章 → 第十四章）

### 2. 准备环境
**目标**：能编译、能运行。
**小节**
1. Rust 版本由 `rust-version` 规定，版本不够时 cargo 自己报错。
2. SDL3 的安装：Linux、macOS、Windows 各一条命令，并给出官方文档链接。
3. 依赖写两个 crate:`he3d` 加一个后端 crate。
4. 没有显示设备时把后端换成 `he3d-platform-std`。
**载体**：sh。
**易犯之处**
- `cargo run` 报后端起不来 → 依赖里只有 `he3d`，没有后端 crate → 加上 `he3d-platform-sdl3`。
- 装完 SDL3 仍然找不到 → 动态库缓存没刷新（Linux）→ `sudo ldconfig`。
**问与答**
- 为什么编译时就要有 SDL3？→ **因为 cargo 编译期就要找到这个库，不是运行时才需要。**（本章）
- 我能不能只用 `StdBackend`？→ **能**：依赖换成 `he3d-platform-std`，类型换成 `StdBackend`，
  画面变成半块字符。（本章 → 第十三章）
**改一改**
- 换成 `StdBackend` 再跑一次，比较终端输出与窗口。
- 把窗口尺寸改成别的值，看画面怎么变。

### 3. 起步
**目标**：先看到东西，再读代码。
**小节**
1. 五条命令：triangle、physics-test、biplane、flight-simulator、playground，各一行，各自看到什么。
2. `-- --frames 60` 让程序跑固定帧数后退出。
**载体**：sh。
**易犯之处**
- `--frames` 不生效 → 它属于程序而不是 cargo → 放在 `--` 之后。
**问与答**
- 为什么示例都硬写 `SdlBackend`？→ **因为后端由二进制指定，示例也是二进制。**（本章）
- `std` 后端画出来的是什么？→ **半块字符**：一个字符单元两个像素，上半前景、下半背景，
  ANSI 24 位色。（→ 第十三章）
**改一改**
- 给任意一条命令加 `-- --frames 5`，看它是怎么退出的。

### 4. 后端
**目标**：知道「用哪个后端」写在哪里。
**小节**
1. `Platform` 是 trait，七个方法：`present`、`poll_events`、`should_close`、`request_close`、
   `time_seconds`、`sleep_ms`、`set_title`。
2. 两个实现：`SdlBackend`、`StdBackend`。
3. 选择就是两步：依赖里加上对应 crate,`main` 里写对应类型名。
4. `trait` 必须在作用域里，否则具体类型的方法找不到。
**载体**：片段。
**易犯之处**
- `backend.present(...)` 报「没有找到方法」 → 方法来自 `trait`，`Platform` 不在作用域 → 把
  `Platform` 写进 `use`。
**问与答**
- 两个后端该用哪个？→ **有显示设备用 `SdlBackend`，没有用 `StdBackend`。**（本章）
- 想自己写一个后端呢？→ 见第十三章。（→ 第十三章）
**改一改**
- 同一个程序只换后端类型与依赖，编一次、跑一次。

### 5. 一个最小程序
**目标**：从零写出一份能跑的程序，每一行都有来历。
**小节**：六段拆解，每段一段代码。
1. 创建后端。
2. 构造场景（资源表、对象、平行光）。
3. 放置对象（网格、纹理、变换、材质）。
4. 设定相机。
5. 创建渲染器。
6. 驱动循环（取事件、更新时间、改场景、绘制、呈现）。
**载体**：完整程序，用 `SdlBackend`，开窗画一个受光的旋转立方体。
**易犯之处**
- 画面抖 → 每帧新建渲染器，跨帧状态被丢 → 渲染器建一次，放在循环外。
- 改了场景画面没变 → 修改发生在 `render` 之后 → 先改场景再绘制。
- `use he3d::Platform` 漏了 → 具体后端的方法来自 trait → 补上。
**问与答**
- `expect` 在程序里可以用吗？→ **可以，但程序会立刻终止（恐慌）。**（本章）
- 引擎为什么自己不跑循环？→ **引擎不拥有你的主循环：`step` 与 `render` 都由你调用。**（本章）
- `present` 为什么单独传宽高？→ **让后端校验**像素缓冲长度与声明尺寸是否相符。（本章）
- 相机朝向怎么算？→ **由你自己算**，第九章给出两行写法。（→ 第九章）
**改一改**
- 立方体尺寸从 `1.0` 改成 `2.0`。
- 物体从 `z = 4` 挪到 `z = 8`，看它怎么变小。
- 视野从 `60.0` 改成 `90.0`。

### 6. 几条贯穿全局的约定
**目标**：拿到五条能解释后面所有设计的规则。
**小节**
1. 句柄而非引用：资源表交出的是 `Copy` 值，资源移除后旧句柄读作 `None`。
2. 数据与绘制分离：场景描述，渲染器画；改动在 `render` 之前不产生可见效果。
3. 时间归应用：引擎不给 `run`、不锁帧率；物理要固定步长，于是有固定步长累加器与两个钳制。
4. 单位由应用定：引擎不规定长度单位，物理的默认值只在 1 单位 = 1 米时有意义。
5. 物理不了解渲染：`he3d-physics` 只依赖 `he3d-math`，看不到 `Scene`、`ObjectId`、`Transform`。
**载体**：片段。
**易犯之处**
- 把句柄当引用长期使用 → 句柄是普通值，可以存，但资源可能已被移除 → 读的时候处理 `None`。
- 以为引擎限帧 → 引擎不限，循环多快由你决定。
- 换成长度单位却不改重力与格子尺寸 → 默认值只在米制下有意义。
**问与答**
- 为什么要代际句柄？→ **因为可以跨帧存**：`Copy` 值，资源移除后旧句柄读作 `None`，不会指向
  复用槽位的新对象。（本章）
- 时间为什么归应用？→ **引擎不拥有你的主循环。**（本章）
- 累加器为什么用 `f64`、物理用 `f32`？→ **累加器长期累加，`f32` 会积累可见漂移。**（→ 第十三章）
**改一改**
- `FIXED_STEP` 从 `1.0 / 120.0` 改成 `1.0 / 30.0`。
- 单帧上限从 `0.25` 改成 `0.05`。

### 7. 资源与材质
**目标**：把画面上那块颜色换成自己的东西。
**小节**
1. 纹理三种来源：`Texture::solid` 纯色、`Texture::new` 由程序生成、`decode_image` 从字节解码
   （文件、网络、内嵌数组都一样）。
2. 材质只有色调：`Material::tint` 乘在采样结果上，只压暗，不提亮。
3. 纹理原点在左上角，`v = 0` 是第一行像素；BMP、PNG、JPEG、glTF 都是这个顺序。
4. 网格：`Mesh::triangle`／`plane`／`cube`／`sphere`／`new`／`from_vertices`；扁平顶点表，
   没有索引缓冲；顶点上限 `MAX_VERTEX_COUNT`。
5. 解码器按特性启用：OBJ 与 BMP 始终可用，`png`、`jpeg`、`gltf` 各自开。
**载体**：片段。
**易犯之处**
- 想用 tint 提亮 → 它只做乘法 → 换更亮的纹理，或调 `scene.light`。
- 换了模型没换碰撞形状 → 物理只看 `Shape` → 两边一起改。
- 手动翻转 `v` → 解码器已按左上原点给出 → 不要翻。
**问与答**
- 共享顶点怎么处理？→ **不共享**：`Mesh` 只存扁平顶点表，共享边上的顶点重复；代价是接缝会被
  当成真实棱边（→ 第十一章）。
- 图片和模型要不要开特性？→ **要**：OBJ 与 BMP 始终可用，其余各自开对应特性。（本章）
- 忘了给纹理会看到什么？→ **一块 2×2 品红与黑相间的棋盘**，一眼看出漏了贴图。（本章）
**改一改**
- 用 `Texture::new` 生成一张棋盘，观察 UV 怎么贴上去。
- tint 从 `Rgb::WHITE` 改成 `Rgb::new(0.5, 0.5, 0.5)`。
- `Mesh::cube` 换成 `Mesh::sphere`。

### 8. 输入与操控
**目标**：让键盘动起来。
**小节**
1. 事件由 `poll_events` 每帧取空；`Event` 两个变体 `KeyDown`／`KeyUp`，枚举非穷尽。
2. `KeyCode` 是 `i32`，ASCII 键小写化，特殊键用常量（`KEY_ESCAPE` 等）。
3. 按键状态存成 `[bool; 256]`：`KeyDown` 置真，`KeyUp` 置假。
4. 按住与按一下：前者读状态数组，后者比较上一帧（边沿检测）。
5. 用按键改物体的 `Transform`。
6. 力与冲量在第十一章。
**载体**：`examples/playground` + 片段。
**易犯之处**
- 用 `KeyDown` 当「按住」 → 系统会发键盘重复事件 → 读状态数组。
- 空格一按跳好几下 → 每帧都判定成「刚按下」 → 记住上一帧，只在 `！was_down && is_down` 时触发。
**问与答**
- 键码怎么比较？→ **`KeyCode` 是 `i32`，ASCII 键已小写化**；特殊键用内置常量。（本章）
- 鼠标事件呢？→ **现在没有**，`Event` 只有按键两个变体。（→ 第十四章）
- 怎么让移动更平滑？→ **输入只决定方向**，平滑交给相机跟随（第九章）与物理（第十一章）。
  （→ 第九、十一章）
**改一改**
- 移动速度调一倍。
- 加一个键让物体绕 `y` 轴转。

### 9. 相机
**目标**：把相机放在该在的地方。
**小节**
1. 相机是普通值：`position`、`orientation`、`fov_y_degrees`、`near`。
2. 朝向用 `Quat`；按角度构造时用 `EulerRot` 指定轴序（追逐相机用 `EulerRot::ZYX`）。
3. 看向一个点：`Quat::from_rotation_arc(Vec3::Z, (target - position).normalize())`。
4. 跟随：先算目标位置（物体位置加偏移），每帧把相机位置朝它挪一部分。
5. 绕轨道旋转：相机位置放在以物体为心的圆上，朝向指向物体。
6. 近裁剪面默认 `0.1`。
**载体**：`playground` + 片段。
**易犯之处**
- 相机在物体正上方时朝向乱跳 → `from_rotation_arc` 在接近反向时只有约 0.001 精度 → 俯仰留余量，
  别正好垂直。
- 近平面设 0 → 逆深度范围被推向无穷 → 保持默认值。
**问与答**
- 怎么让相机看向一个点？→ **`Quat::from_rotation_arc(Vec3::Z, (target - position).normalize())`**；
  追逐类相机用「偏航＋固定俯仰」更稳（`examples/flight-simulator` 的 `update_camera`）。（本章）
- 视野是水平还是垂直？→ **垂直**（`fov_y_degrees`），16:9 下水平更大。（本章）
- 相机要交给渲染器保管吗？→ **不**，`render` 每帧收一次引用，随时可以改。（本章）
**改一改**
- `fov_y_degrees` 从 `60.0` 改成 `90.0`。
- 跟随距离减半。

### 10. 画面质量：分辨率与抗锯齿
**目标**：知道该调哪个旋钮、代价是什么。
**小节**
1. 开销按像素算：与分辨率成正比，与三角形数关系小。
2. `AntiAliasing` 五个变体：`None`、`Msaa`（每像素四样本）、`Fxaa`（后处理按亮度糊边）、
   `Taa`（Halton 抖动＋上一帧历史）、`Ssaa(scale)`（内部超采样后盒式降采样）。
3. 怎么设：`RendererConfig` 的 `anti_aliasing` 字段。
4. 像素预算：内部缓冲受 `MAX_FRAMEBUFFER_PIXELS` 约束，`Ssaa` 的 scale 受 `MAX_SSAA_SCALE` 钳制。
5. TAA 依赖跨帧状态，因此渲染器只建一次。
**载体**：片段。
**易犯之处**
- 画面抖 → TAA 开着而渲染器每帧重建 → 渲染器建在循环外。
- 以为分辨率翻倍只慢一倍 → 像素数翻两番 → 先降分辨率。
**问与答**
- 几种抗锯齿怎么选？→ **静止难看选 `Msaa`；只要质量不在乎开销选 `Ssaa`；最便宜选 `Fxaa`；
  运动收敛选 `Taa`**——TAA 依赖跨帧状态。（本章）
- `Ssaa(scale)` 能开多大？→ **受 `MAX_SSAA_SCALE` 钳制**：内部缓冲是 scale² 倍再乘样本数。（本章）
- 帧率不够先从哪调？→ **分辨率**；光栅化按像素计费，削场景收效小。（本章）
**改一改**
- 同一场景依次试 `None`、`Msaa`、`Fxaa`、`Taa`、`Ssaa(2)`，记下帧时间。
- 输出分辨率减半。

### 11. 物理
**目标**：让东西掉下来、碰到东西、睡着。
**小节**
1. `World::new`、`BodyDesc::dynamic`／`stationary`／`kinematic`、`Shape::cuboid`（收半长）／
   `sphere`（收半径）。
2. 三种运动模式各是什么。
3. 关联由应用拥有：`Thing { body, object }` 加一个每帧复制位姿的函数。
4. 每步发布接触表：双方、接触点、法线、深度、阶段（`Begin`／`Persist`／`End`）。
5. 睡眠以岛为单位：稳定后不再计算，扰动一个成员全岛醒来。
6. 静态几何注册三角形网格，焊接进同一套共享拓扑。
7. 力只作用一步：`apply_force`／`apply_torque` 在下一次 `step` 生效随后清空，`apply_impulse`
   是一次性速度变化。把按键变成力与冲量（承接第八章）。
**载体**：片段 + `playground` 的推箱子。
**易犯之处**
- 物体睡着后查不到接触 → 它不再产生约束 → 要问就先 `wake`。
- `remove_body` 之后还用旧编号 → 编号带代际，移除后读作 `None` → 删掉对应表项。
- 忘了每帧复制位姿 → 物理在动、画面不动 → 每帧调用同步函数。
**问与答**
- 碰撞体怎么缩放？→ **不缩放**：物理没有缩放这个概念，要更大的碰撞体就指定更大的 `Shape`，
  `Transform.scale` 只影响画面。（→ ADR 0001）
- 物体睡着后还能查到接触吗？→ **不能**，睡着的物体不产生约束。（本章）
- 一对物体会产生几条接触？→ **可能多条**，接触流形按面产生。（→ 第十二章）
**改一改**
- 质量从 `1.0` 改成 `0.0`。
- `with_restitution` 从 `0.4` 改成 `0.9`。

### 12. 物理进阶
**目标**：把物理调成想要的手感。
**小节**
1. 三种运动模式的用法：`kinematic` 当运动平台、`stationary` 当关卡。
2. 阻尼：`with_damping`／`set_damping`。
3. 质量与惯量：质量是输入，惯量由形状与质量推出。
4. `World` 三个调参口：`set_broadphase_cell_size`、`set_velocity_iterations`、`set_static_friction`。
5. `gravity_scale`：`0.0` 表示不受重力但仍参与碰撞。
6. 读状态：`position`、`orientation`、`velocity`、`mass_properties`、`aabb`。
**载体**：片段。
**易犯之处**
- 宽阶段格子比物体还小 → 一个物体跨很多格 → 格子尺寸取比最小物体略小。
- 把速度迭代次数当画质旋钮 → 它影响穿透与堆叠稳定性 → 先调质量、阻尼与摩擦。
**问与答**
- 宽阶段格子该多大？→ **比场景里最小的物体略小**（`DEFAULT_CELL_SIZE` 是 2.0）。（本章）
- 惯量张量在哪设？→ **不设**：输入质量，惯量由形状与质量推出。（本章）
- `Kinematic` 和 `Static` 差在哪？→ **`Static` 永不移动，`Kinematic` 每步按你设的速度移动**，
  并以无穷大质量推动别人。（→ 第十一章）
**改一改**
- 给盒子加 `with_damping(0.5, 0.5)`，比较按住方向键时的速度。
- 把 `gravity_scale` 设为 `0.0`，看它是否仍然参与碰撞。

### 16. 为什么这样设计
只写四条，都是读者不知道就会走错路的：
1. 物理与渲染之间没有绑定层：关联由应用保存，每帧复制位姿（ADR 0001）。
2. 资源用代际句柄指代：交出引用会把借用跨帧铺开。
3. 静态几何焊接进同一套共享拓扑：否则接缝会被当成棱边，物体卡住。
4. 睡眠以岛为单位：抽走最底层时，上面几层要一起醒。

其余取舍写在 `docs/adr/`。不设问与答、不设改一改。
