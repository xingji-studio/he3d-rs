## 一、HE3D 是什么

本章说明这套引擎是什么、画面在哪里产生、开销按什么计量。判断一个项目是否适合使用它，所需的事实只有这三项。

HE3D 是一套用 Rust 编写的软件 3D 引擎：场景在 CPU 上逐像素光栅化为一块 RGBA 像素缓冲，再由呈现后端送出。它由四部分构成：光栅化器、场景与资源的容器、刚体模拟、呈现后端。物理与渲染彼此独立，物理不认识场景，渲染不认识物体与渲染对象之间的关联，两者的联系由应用保存。

### 画面在哪里产生

场景由渲染器（`Renderer`）在 CPU 上光栅化。三角形覆盖到的每个像素都要经过同样的步骤：深度测试、纹理采样、着色，随后写进一块 RGBA 像素缓冲。每次绘制都重画整个场景；渲染器跨帧保留的只有抗锯齿所需的历史，画面本身不继承上一帧。绘制完成后，像素与宽高一起交给呈现后端送出：可以是一个窗口，可以是终端里的半块字符，也可以是任何实现了后端接口的类型。渲染器不认识窗口，也不认识任何后端类型。

由此得到的是可移植性：没有 GPU 依赖，没有着色器语言，也没有对图形 API 的包装；库本身可以在没有标准库的目标上构建，没有显示设备时同一份绘制结果可以输出到标准输出。代价落在像素数上：一帧写入的像素越多，这一帧越慢，而三角形数量对此的影响小得多。需要追回帧率时，先降低分辨率；削减场景规模收效甚微。（→ 第十章）

物理与渲染共用同一颗 CPU，两份开销争夺同一份时间预算，像素总量因此设有硬上限：内部像素数超出上限的渲染器配置在构造时就被拒绝，而不是等到运行时才发现画不出画面。（→ 第十章）

### 三条约定

以下约定贯穿全部接口：

| 项目 | 约定 |
|---|---|
| 手性 | 右手系 |
| 上方向 | `+Y` |
| 前方向 | `+Z`，朝向为单位四元数的相机沿 `+Z` 观察 |
| 深度 | 逆深度（`1/w`），值越大越近；设有近裁剪面，未设远裁剪面 |
| 纹理原点 | 左上角，`v = 0` 对应首行像素 |

三个坐标轴连同手性一起确定了「前」是哪一侧：右手系中 `x` 向右、`y` 向上、`z` 向前，因此相机看向前方即看向 `+Z`，位于相机前方的物体其 `z` 分量大于相机的 `z` 分量。

**物体落在相机背后** → 引擎以 `+Z` 为前方，按 `-Z` 摆放的物体其 `z` 小于相机的 `z` → 表示前方用单位向量 `Vec3::Z`。

深度缓冲保存的是距离的倒数而非距离本身，因此数值越大越近。这样做的效果是近处的精度远高于远处，代价是远处两个物体的前后关系可能无法分辨；由于不存在远裁剪面，远处的物体不会被裁掉，只是先后顺序可能出错。

**远处的遮挡关系反了** → 深度按 `1/w` 存储，当成距离来读就反了过来 → 需要可靠的远近关系时把物体放在近处，远处的先后顺序无法保证。

近裁剪面默认 0.1，不能设为 0：近平面落在眼睛处时，逆深度范围远端的精度会被推到无穷，近处的精度随之毁掉。

纹理原点在左上角，与 BMP、PNG、JPEG 的存储顺序一致；OBJ 在解码时转到这个约定，glTF 本身就按这个顺序存储。因此读取时无须翻转 `v`，翻转反而会让贴图上下颠倒。

**贴图上下颠倒** → 解码器已按左上原点给出 `v`，再翻一次就倒了 → 不手动翻转 `v`。

### 易犯之处

- 物体落在相机背后：见「三条约定」。
- 远处的遮挡关系反了：见「三条约定」。
- 贴图上下颠倒：见「三条约定」。

### 问与答

- **逆深度换来什么，代价是什么？** → **换来近处的精度，并且不需要远裁剪面**；代价是远处两个物体的前后关系可能分不清。近裁剪面因此不能取 0，默认值为 0.1。
- **这套引擎适合做什么？** → **可控规模的低多边形场景，以及需要可移植或没有显示设备的场合。** 它不依赖 GPU，库可以在没有标准库的目标上构建，画面也可以输出到标准输出。（→ 第十三章）追求画质的项目不适合：没有 GPU，没有着色器，画面质量可用的手段只有分辨率、纹理与几种抗锯齿。（→ 第十四章）
