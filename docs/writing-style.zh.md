# 文档写作规范

本文件规定 HE3D 文档的语言、文体、术语与结构。它约束 `README.md`、`docs/` 下面向使用者
的文档，以及 `CONTEXT.md`、`AGENTS.md` 与 `docs/adr/` 的语言选择。源码注释不在其内：
注释双语并列，因为它们在 rustdoc 与编辑器中无法分文件呈现。

本文件自身遵循它所规定的文体。

---

## 一、语言与文件

面向使用者的文档以两份文件存放，文件名配对：

```
README.md            README.zh.md
docs/getting-started.md      docs/getting-started.zh.md
docs/physics-spec.md         docs/physics-spec.zh.md
```

不带后缀的一份为英文，带 `.zh.md` 的一份为中文。两份内容等价，**句子无须逐字对应**：
中文承担概念的中文名称，英文不需要这层转写，因此英文通常更短，标识符出现得更早。
强行逐句对齐，两边都会走样。

**中文先写。** 一篇文档的中文定稿之后，英文才由它译出。因此内容的最新版本在中文一侧，
英文可能滞后。滞后是允许的，缺失不是：每篇文档都应有两份。

三份内部文档例外，各自用英文单语，不做配对：`CONTEXT.md` 是术语表，供全仓库与工具
引用；`AGENTS.md` 供工具读取；`docs/adr/` 是长期推理记录，其中的取舍与另一条路都写在
英文语境里。它们面向的是下一次修改这份代码的人与程序，而不是第一次使用引擎的人。

`docs/plans/` 放内部工作文档（大纲、改写计划），中文单语，不配对，也不面向使用者；对应
正文定稿后即可删除。

每份配对文件的首行放置语言切换：

```
[English](getting-started.md) | 中文
```

### 正文与代码

正文里的标识符遵循一条规则：**散文说东西，代码说名字。**

类型名、方法名、字段名、枚举变体与常量，首次出现时以「中文概念（`标识符`）」的形式标注
一次，此后正文可用内联 code 直接指代，不必每次重复中文概念词：内联指代的用处是让读者
在代码里找得到它，不是把代码念一遍。**描述行为仍用中文动词。**

| 不写 | 写成 |
|---|---|
| `World` 拥有 `Body`，`Scene` 拥有 `RenderObject` | 物理世界（`World`）持有物体（`Body`），场景（`Scene`）持有渲染对象（`RenderObject`） |
| 调用 `present` 把像素缓冲交给后端 | 呈现（`present`）把像素缓冲交给后端 |
| 接触的双方是 `ContactPartner::Body` 或 `ContactPartner::Static` | 接触的双方可能是一个物体，也可能是一块静态几何 |

一句话里出现两个以上标识符时改用中文概念词。小节标题里不出现标识符，代码块中的注释
不受本规则约束。

代码块中的注释随所在文件的语言翻译。两个文件中的**代码本身必须逐字相同**，只有注释
不同。

**代码块由 `crates/he3d-docs` 编译。** 那个 crate 的 `build.rs` 把指南里每个 `rust`
代码块抽出来，生成一个模块交给编译器，因此 `cargo clippy --workspace --all-targets`
会一并检查它们；指南一旦与 API 脱节，构建即失败。**指南文件里不留任何痕迹**：没有隐藏
行，没有 `no_run`，没有围栏属性。指南首先是给 GitHub 与编辑器预览看的，其次才轮到编译器。

片段需要而自身没有显示的上下文由 `build.rs` 补齐，分两层：取自那段完整程序的片段自动
带上**程序自己的 import**（程序在该处本来就处于这些名字的作用域内）；只有用到程序之外的
名字，或者需要程序在此之前的变量时，才要在 `CONTEXTS` 里加一条，键是片段的首行。因此
新写一个只用常见类型与构造函数的片段，通常一个字都不用补。

**该编译不过的片段另立一张 `FAILING` 表。** 「易犯之处」里的反例也是代码，只是它们编译
通过便算失败；表的键同样是片段首行，校验由 `he3d-docs` 的测试完成。指南里贴出的报错
原文因此不会随 rustc 版本悄悄腐烂。

只编译，不运行。指南里的程序会打开终端并等待按键，测试运行不该做这件事；真正运行引擎
是 `examples/` 与各 crate 测试套件的事。

`CONTEXTS` 里漏一条会在编译期报「找不到名字」；条目与片段对不上则会收到一条
`cargo:warning`，指明哪条成了孤儿。

完整程序仍然住在 `examples/`，由 CI 编译并运行；指南里的是讲解用的版本。

## 二、正文

### 句子

以书面语写作，不追求简短。正式的连接词是句子之间的关节：因此、因而、然而、也就是
说、值得注意的是、相比之下、顺带、事实上。两个短句之间有因果关系时，合并为一句。

「也就是说」作连接词可用，它后面那种把前半句换个说法再讲一遍的同位语不用：写「帧缓冲
存着画面」，不写「帧缓冲，也就是一整块 RGBA 像素」。口语量词同样换掉：一整块、一大堆、
好几圈。

不使用文言虚词。「故」「则」在所参照的四份中文文档（Rust 官方中文版、
Programming Rust 中译、Vue 官方中文、MDN 中文）中均未出现；「若」只零星见于后两份，
不足以成为惯例。

### 人称

**人称代词一概不用。** 无主句、名词化，或以「需」「应」「可」表达，都能替代人称代词：
「你」「我」「我们」不出现在正文中，「自己」这类反身代词同样不用。

| 不写 | 写成 |
|---|---|
| 你可以用不同的方式启动后端 | 启动后端的方式有多种 |
| 我们需要先安装 SDL3 | 需先安装 SDL3 |
| 你可以在它醒着的时候问它 | 应在它仍清醒时发问 |
| 你必须在下一次 step 之前调用 | 须在下一次 `step` 之前调用 |
| 引擎自己不跑循环 | 引擎不拥有主循环 |
| 相机朝向由你自己算 | 相机朝向由应用计算 |

### 动词

避免单音节口语动词，改用书面动词。

| 不写 | 写成 |
|---|---|
| 开一个窗口 | 呈现于一个窗口 |
| 搭场景 | 构造场景 |
| 放相机 | 设定相机 |
| 进循环 | 驱动循环 |
| 看完这一节 | 阅读本节之后 |
| 对接渲染层 | 与渲染层衔接 |
| 落地这套接口 | 实现这套接口 |

行话同理。「对接」「赋能」「落地」「闭环」一类词来自会议而非文档，出现时应替换为具体
的动词：连接、实现、完成、对应。

### 不拟人

数据结构不具有意志。避免「这边」「那边」「这里」「那里」「手上」「只认」「互不相识」
这类说法；指示位置改用具体名词：帧缓冲、场景、后端、循环。

| 不写 | 写成 |
|---|---|
| 模拟这边只认自己手上的物体 | 前者持有物体 |
| 两个编号互不相识 | 两个编号之间没有关联 |
| 睡着的物体不说话 | 睡着的物体不再产生约束 |

### 不写元叙述，也不与过去或讨论作对比

不解释文档自身为何如此编排，亦不替自己的取舍辩解。判断标准是该句描述的是引擎，
还是本文；后者属于此类。

| 不写 | 处理 |
|---|---|
| 它被 CI 编译，因此可以照抄 | 删去 |
| 用户要求中英文分开，所以这里拆成两个文件 | 删去 |

**正文只写现在是什么、怎么做。** 不写「不是 X 而是 Y」「以前是 X」「曾经考虑过 X」
「有人建议 X」，也不写「之所以没有 X，是因为……」。这类句子把读者拉进一段他没参与过的
讨论，而他只需要知道现在怎么做。**去掉一样东西时就只是去掉**，不补一段它为什么不在；
按现在的样子写。

设计取舍只在篇末「为什么这样设计」里说，而且只在读者需要它才能建立正确心智模型时才说。
对比的对象是**另一条设计路线**，不是过去的做法，也不是谁提过的意见。

## 三、幽默

**幽默藏在例子里，正文一句俏皮话都不写。**

Programming Rust 讲除以零，开篇是海盗分赃：船长取一半，余数分给船上的鹦鹉。正文本身
从头到尾没有一句玩笑，它只是说「这段代码也许可以工作几个世纪，直到有一天船长是抢劫
之后唯一的幸存者」。

对照之下，这类句子属于该删之列：

| 删 |
|---|
| 这是物理接口里最容易浪费掉一个下午的地方 |
| 填充率才是帧预算。想要帧数回来，先降分辨率——把场景删掉一半通常没什么用 |

后者的问题不在于不准确，而在于**在句子里讲笑话**。改为在例子里体现，正文保持平实。

工具难用时可以直接说明，但须说得准确，不加形容词：

> 错误消息在干扰中丢失。`RUST_BACKTRACE=1` 也是一个错误的建议。

### 反问与破折号

反问可用于段落转折，但**用过之后必须立即回答**，且全篇至多一两处。破折号同理：
它常被用来插入一句本可以写成正常从句的话，因此除非确实需要，不改用破折号。

## 四、术语与标点

术语在首次出现时标注一次英文，此后固定使用同一种形式，不再中英并列。

- 引擎自身的概念保留英文不做翻译：Body、Island、warm starting、Static geometry、trait。
  这些名称已固定在 [`CONTEXT.md`](../CONTEXT.md) 与各篇 ADR 中。
- 通用概念给出中文名称，首次出现时在括号内附英文：代际句柄（generational handle）、
  逆深度（inverse depth）。
- 代码标识符一律保持英文原样，包括出现在正文中时。
- 不自造译名。`trait` 就写 `trait`，不写「契约」「特型」一类同义词——同一件事在全书里
  只有一个名字。

标点规则取自 MDN 中文：

- 使用全角标点。
- 中文与拉丁字母、数字之间留一个半角空格：「渲染器（`Renderer`）持有帧缓冲区」。
- 保留的英文术语不加复数 s：写 `RenderObject`，不写 `RenderObjects`。
- 段落不长于两百字时不强行断行，段落内不断行。

## 五、结构

**每讲一个概念，紧接一段可运行的代码。** 不要积攒若干概念之后集中举例。

### 长篇指南的章节

面向使用者的长篇指南（`docs/getting-started.zh.md` 一类）每章六段，顺序固定：

1. 一句话：本章解决什么。
2. 能跑的代码。
3. 逐段解释。**易犯之处就在这一段里就地给出**：读者读到会出错的那一行，警告在那一行
   旁边，写成「症状 → 原因 → 怎么办」。涉及编译失败的，连 rustc 的错误码与消息一起贴，
   不转述；随机器变化的源码路径可用 `...` 省略。
4. 易犯之处：三条以内的索引，每条一行，指明它出现在第三段的哪一小节。索引不重述正文。
5. 问与答。
6. 改一改：两三条动手就能看到结果的改动。

只做索引或取舍汇总的章节不设问与答。

### 问与答

**先给结论**（能／不能、该／不该、是／不是），再给机制，最后才是指针。

| 不写 | 写成 |
|---|---|
| 见第七章 | 能编，不能跑。构建只要库与头文件；开窗口才要显示设备。（→ 第七章） |

问题可以因为太深而交叉引用到后面讲透它的那一章，**指针是螺旋的一部分**；但它不能代替
答案——只给指针不给结论，等于没回答。问题要写成读者真会问的，包括追问。

问与答与正文一一对应：正文里那个坑的旁边留一个短标记（「见问与答」），问与答里的问题
注明它出自哪一小节，两边互相找得到。

**文档里不写待做的题。** 没有答案的练习题没人批改，也没人做。「改一改」之所以留下，
是因为每一改都能当场看到结果。

### 螺旋

同一个概念在全篇有多次落点：首现只给够用的深度，章末问与答里被追问一次，再由问与答
指向讲透它的后章。正文里需要时可以插一个短标记，指向本章问与答。写正文时若发现某处
非展开三层不可，那是落点没排好，不是该写长。

### 篇末的「为什么这样设计」

**每篇末尾设一节「为什么这样设计」**，这类内容不放在正文中充当插入语。

只写读者需要它才能建立正确心智模型的取舍。**没必要就不说**：读者照着现在的写法不会走错
路，就不解释；少了某个部件，也不解释它为什么不在。对比对象是另一条设计路线，不是过去的
做法，也不是谁提过的意见。

### 标题

章节标题译为中文，代码标识符与类型名不译。标题长度以能概括该节为准，不必求短，但不用
口语。

| 不写 | 写成 |
|---|---|
| 先把画面跑起来 | 起步 |
| 物理那点事 | 物理 |

## 六、自检

定稿前逐条核对：

- [ ] 正文中是否出现了「您」「你」「我」「我们」「自己」？
- [ ] 是否存在连续的短句，本可合并为一句？
- [ ] 是否出现了「这里」「那里」「这边」「那边」「手上」「只认」等指示位置或拟人的说法？
- [ ] 是否有「帧缓冲，也就是一整块 RGBA 像素」这类口语同位语，或「一整块」这类口语量词？
- [ ] 是否出现了「对接」「赋能」「落地」「闭环」等行话？
- [ ] 是否出现了「故」「则」「若」等文言虚词？
- [ ] 正文里是否连续出现了两个以上的标识符？
- [ ] 是否有句子在讲笑话？若有，移入例子。
- [ ] 是否有句子在解释本文自身的编排？
- [ ] 是否有句子在与过去或某次讨论作对比（「以前」「曾经」「不是 X 而是 Y」「之所以没有 X」）？
- [ ] 每讲一个概念，后面是否跟着代码？
- [ ] 术语是否只在首次出现时标注英文？是否自造了译名（如把 `trait` 写成「契约」）？
- [ ] 中英之间是否留有空格？标点是否为全角？
- [ ] 篇末是否有「为什么这样设计」一节？其中的理由是否都必要？
- [ ] 长篇指南的章节是否有问与答？问与答是否先给了结论，而不是只给指针？
- [ ] 易犯之处是否就地出现在第三段，章末只剩索引？
- [ ] 贴出的编译器报错是否与当前工具链一致？反例是否登记在 `FAILING` 表里？
- [ ] 标题是否口语？
- [ ] 是否写了没有答案的题？
- [ ] `CONTEXT.md`、`AGENTS.md`、`docs/adr/` 是否只用了英文，没有跟着配对？
